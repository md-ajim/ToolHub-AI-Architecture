# 00.9 --- Master Implementation Verification & Compliance

## ToolHub AI --- Documentation-to-Implementation Final Assurance Gate

**Version:** 1.0\
**Status:** Mandatory Verification Specification\
**Release Status:** NOT VERIFIED until implementation evidence is
recorded.

------------------------------------------------------------------------

## Purpose

This is the final verification layer for ToolHub AI. It does **not**
replace the existing documentation. It verifies that implementation
follows the existing documentation, preserves approved functionality,
and does not silently introduce architecture, UX, security, performance,
SEO, accessibility, billing, AI, or compatibility regressions.

The project is not complete merely because a page renders. A release
requires documentary, architectural, functional, security, responsive,
accessibility, performance, testing, and visual evidence.

------------------------------------------------------------------------

## Source-of-Truth and Order

The authoritative workflow is:

``` text
Read Documentation
↓
Understand Architecture
↓
Understand Dependencies
↓
Create Plan
↓
Approval when required
↓
Implement
↓
Test
↓
Self Review
↓
Update Documentation
↓
Verify Architecture
```

If documentation conflicts:

1.  Do not guess.
2.  Identify the conflict.
3.  Preserve existing architecture.
4.  Obtain approval for an architectural change.
5.  Update the affected documentation.

------------------------------------------------------------------------

## Non-Negotiable Preservation Rule

A redesign/refactor/editor/AI-workspace change must not silently:

-   delete an existing tool
-   remove an existing API
-   rename APIs, routes, models, folders, or database tables without
    approval
-   remove workflows, history, project state, export, authentication,
    authorization, or entitlement behaviour
-   bypass centralized business rules
-   create duplicate implementations of existing capabilities

If deprecation is genuinely required:

``` text
Reason → Impact Analysis → Replacement/Migration → Approval
→ Deprecation → Compatibility Handling → Documentation → Tests
```

**No silent deletion.**

# 36. Mandatory Agent Self-Review

Before declaring any task complete, the coding agent must answer:

1.  What documentation was read?
2.  What architecture was used?
3.  What existing functionality was preserved?
4.  What changed?
5.  What did not change?
6.  Was any functionality duplicated?
7.  Was any API, route, model, table, folder, or architecture changed?
8.  If yes, where is approval?
9.  What tests were run?
10. What visual QA was performed?
11. What security checks were performed?
12. What responsive/accessibility checks were performed?
13. What documentation was updated?
14. What evidence proves it works?
15. Are any requirements `BLOCKED`, `PENDING`, or `FAIL`?

If a critical answer is unknown, the task is **not complete**.
