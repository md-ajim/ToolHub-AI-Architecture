## v1.1 Addendum --- Public Discovery vs Application Navigation

``` text
Public Mega Menu
→ discover categories and public tools

Application Sidebar / Tool Rail
→ work with tools inside the workspace

Global Search
→ discover public or workspace content according to scope
```

The Mega Menu is for public discovery and must not be rendered as the
full public navigation inside focused AI/editor workspaces.

`Pricing`, `Blog`, public `Tools`, and other marketing links remain
outside the application shell.

Categories must stay synchronized with the Tool Registry.

## ToolHub AI --- Professional Tool Discovery & Navigation System

> Status: Master Mega Menu & Tool Discovery Specification\
> Purpose: Define the category structure, tool organization, navigation
> behavior, visual hierarchy, and scalability of the ToolHub AI Mega
> Menu.

------------------------------------------------------------------------

## 1. Product Objective

ToolHub AI must feel like a professional AI-powered creative software
platform rather than a collection of unrelated online tools.

The Mega Menu is a primary product-navigation surface. It should
communicate that ToolHub AI provides a broad, organized ecosystem for
image editing, AI workflows, optimization, product photography, design,
and professional creative work.

The navigation must be:

-   Large and professional
-   Easy to understand
-   Scalable
-   Fast
-   Searchable
-   Brand-consistent
-   Workflow-oriented
-   Future-ready

The goal is **not** to copy another platform. Competitors may be studied
for user expectations and information architecture, but ToolHub AI must
use its own brand, components, tokens, icons, and interaction patterns.

------------------------------------------------------------------------

# 2. Core Navigation Principle

The primary relationship is:

``` text
Mega Menu

    ↓
Tool
    ↓

```

Example:

``` text

  ↓
Resize & Crop
  ↓

```

A tool should not be treated as an isolated page when a richer
editor/workflow can provide a better experience.

# 19. Mega Menu Size

The Mega Menu should be significantly larger than a standard dropdown.

Recommended desktop container:

``` text
width: min(94vw, 1280px)
```

For larger screens, a maximum width around `1280px–1400px` may be used
if consistent with the global layout.

Recommended maximum height:

``` text
70vh–80vh
```

If content exceeds the viewport:

-   use internal scrolling
-   keep navigation stable
-   preserve the featured area
-   never push the entire page out of the viewport

Do not make the menu unnecessarily oversized just for visual impact.

# 24. Central Tool Registry

Do not maintain separate hardcoded tool lists in:

-   Mega Menu
-   Tools Directory
-   Search
-   Category pages
-   Sitemap
-   Related tools
-   Editor

Instead, use a centralized Tool Registry.

Conceptual model:

``` ts
{
  id: "image-resizer",
  name: "Image Resizer",
  category: "resize-crop",
  description: "...",
  icon: "...",
  route: "/tools/image-resizer",
  editorRoute: "/tools/image-resizer/editor",
  pricing: "free",
  featured: false,
  popular: true,
  status: "available"
}
```

Pricing values:

``` text
free
pro
freemium
```

Status values:

``` text
available
beta
coming-soon
deprecated
```

The registry becomes the single source of truth.

# 31. Accessibility

The Mega Menu must support:

-   keyboard navigation
-   Escape to close
-   Enter to activate
-   visible focus states
-   screen-reader labels
-   sufficient contrast
-   touch-friendly targets

Hover must never be the only way to access functionality.

------------------------------------------------------------------------

# 32. Interaction Behavior

Desktop:

-   click opens the menu
-   hover may preview categories
-   moving between categories should not cause accidental closure
-   clicking outside closes the menu
-   Escape closes the menu

Mobile:

-   tap to open
-   category navigation
-   back navigation
-   no hover dependency

------------------------------------------------------------------------

# 33. Performance

The Mega Menu must remain fast.

Do not load heavy tool assets when the menu opens.

Prefer:

-   lightweight metadata
-   optimized icons
-   lazy-loaded featured media
-   cached registry data
-   lazy category content

------------------------------------------------------------------------

# 34. SEO

stuffing.

# 39. Final Rule

The Mega Menu should make ToolHub AI feel larger **because the product
is genuinely becoming more capable**, not because the navigation is
artificially crowded.

Every new category and tool must answer at least one question:

> Does this help users accomplish a real task?

If yes, it can be added to the ecosystem.

If not, it should not be added merely to increase tool count.
